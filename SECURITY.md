# Security Policy

This document describes the security expectations and guidelines for the Maestro project.

## Supported Versions

Maestro is currently in active development. Security updates apply to the latest version only.

## Reporting a Vulnerability

If you discover a security issue:
- Do not open a public GitHub issue.
- Contact the maintainer privately.
- Provide a clear description of the issue and steps to reproduce.

## Security Principles

- Maestro runs entirely on the user's local machine.
- No external API calls are made by default.
- No user data is transmitted to remote servers.
- All LLM inference is performed locally through Ollama.
- WebSocket communication occurs only within localhost.

## Recommended Local Security Practices

- Run Maestro on a trusted machine.
- Do not expose the FastAPI server to the public internet.
- Keep Python and dependencies updated.
- Use a firewall to restrict external access.
- Avoid running untrusted code generated by agents.

## Data Handling

- Maestro does not store personal data.
- Conversation state exists only in memory.
- No logs are uploaded or transmitted externally.

## Dependencies

- Review third‑party libraries for vulnerabilities.
- Keep Ollama and AutoGen updated.
- Use virtual environments to isolate dependencies.

## Disclaimer

Maestro is provided as‑is. Users are responsible for securing their own environment.
